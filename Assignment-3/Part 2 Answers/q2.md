2. What is the purpose of the `dispatch` function? How does it work?

## Purpose of `dispatch` Function

The `dispatch` function performs a **context switch** from the current thread to another thread. It saves the state of the currently running thread and restores the state of the next thread to run, effectively transferring control of the CPU from one thread to another.

## How `dispatch` Works - Detailed Explanation

### Function Signature
```c
static void dispatch(thread next)
```
- `next`: Pointer to the thread_block that should be executed next

### Function Code
```c
static void dispatch(thread next) {
    if (current != NULL) {
        if (setjmp(current->context) == 0) {
            current = next;
            longjmp(next->context, 1);
        }
    } else {
        current = next;
        longjmp(next->context, 1);
    }
}
```

## Step-by-Step Execution Flow

### Case 1: When `current` is NOT NULL (Normal Context Switch)

**Step 1: Check if Current Thread Exists (Line 145)**
```c
if (current != NULL) {
```
- Most common case during normal operation
- There's a currently running thread that needs to be saved

**Step 2: Save Current Thread's Context (Line 146)**
```c
if (setjmp(current->context) == 0) {
```
- **Saves the entire CPU state** (registers, program counter, stack pointer) of the current thread
- Returns 0 on first call (when saving context)
- Returns non-zero when resumed later (when another thread dispatches back to this one)

**Step 3: Update Current Thread Pointer (Line 147)**
```c
current = next;
```
- Updates the global `current` pointer to point to the next thread
- From this point on, `current` refers to the new thread

**Step 4: Restore Next Thread's Context (Line 148)**
```c
longjmp(next->context, 1);
```
- **Restores the CPU state** from the next thread's saved context
- Execution jumps to where that thread left off (at its setjmp call)
- **This function never returns normally** - execution continues in the next thread
- The next thread's setjmp will return 1

### Case 2: When `current` is NULL (First Thread Start)

**Step 1-2: No Current Thread to Save (Lines 150-151)**
```c
} else {
    current = next;
```
- Happens when starting the very first thread or after a thread terminates
- No context to save, so skip directly to setting `current`

**Step 3: Start the Thread (Line 152)**
```c
longjmp(next->context, 1);
```
- Jumps to the thread's saved context
- The thread begins execution

## What Happens During Context Switch

### Before dispatch(threadB):
```
Current Thread: threadA
CPU State: Running threadA's code
Stack: Using threadA's stack
```

### During dispatch(threadB):
```
1. setjmp saves threadA's CPU state to threadA->context
   - Program counter (where to resume)
   - Stack pointer (threadA's stack position)
   - All registers (r0-r15, etc.)

2. current = threadB (update global pointer)

3. longjmp restores threadB's CPU state from threadB->context
   - Program counter restored (jumps to threadB's code)
   - Stack pointer restored (now using threadB's stack)
   - All registers restored
```

### After dispatch(threadB):
```
Current Thread: threadB
CPU State: Running threadB's code
Stack: Using threadB's stack
```

## Key Concepts

### 1. **Context Switching is CPU State Swapping**
A context includes:
- **Program Counter (PC)**: Where the thread is in its code
- **Stack Pointer (SP)**: Position in the thread's stack
- **Registers**: All CPU registers (r0-r15 on ARM)
- **Status Flags**: Condition flags, interrupt state

### 2. **setjmp Returns Twice**
```c
if (setjmp(current->context) == 0) {
    // Executes when SAVING context (first call)
    // Continue with context switch
} else {
    // Executes when RESUMING this thread later
    // Some other thread called dispatch() to come back here
}
```

### 3. **dispatch Never Returns Normally**
The function appears to return, but actually execution continues in a completely different thread. The original calling thread is paused until some other thread dispatches back to it.

### 4. **Cooperative Multithreading**
Threads must explicitly call `yield()` or finish to give up CPU. The dispatch function is the mechanism, but threads control when it's called.

## Example Execution Trace

```c
// Thread A is running
void threadA_function(int arg) {
    printf("A1\n");
    yield();           // Will call dispatch internally
    printf("A2\n");    // Resumes here later
}

// Thread B
void threadB_function(int arg) {
    printf("B1\n");
    yield();           // Will call dispatch internally
    printf("B2\n");    // Resumes here later
}
```

**Execution Order:**
```
1. "A1" printed by Thread A
2. Thread A calls yield()
3. yield() calls dispatch(threadB)
4. Thread A's context saved
5. Switch to Thread B
6. "B1" printed by Thread B
7. Thread B calls yield()
8. yield() calls dispatch(threadA)
9. Thread B's context saved
10. Switch back to Thread A
11. Thread A resumes at yield() (after dispatch returns)
12. "A2" printed by Thread A
```

## Where dispatch is Called

In TinyThreads, `dispatch` is called from:

1. **yield()** - Voluntary context switch
   ```c
   dispatch(dequeue(&readyQ));
   ```

2. **spawn()** - When a thread finishes execution
   ```c
   dispatch(dequeue(&readyQ));
   ```

3. **Future: Scheduler/Timer interrupts** - Preemptive scheduling

## Summary

The `dispatch` function:
1. **Saves** the current thread's CPU state using setjmp
2. **Updates** the `current` pointer to the next thread
3. **Restores** the next thread's CPU state using longjmp
4. **Transfers control** to the next thread seamlessly

This is the **heart of the threading system** - the mechanism that allows multiple threads to share a single CPU by rapidly switching between them.
