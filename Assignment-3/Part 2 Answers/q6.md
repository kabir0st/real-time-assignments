6. After finishing the execution of line 96 (spawn(computePower, 0)), describe the content of `freeQ`.

## Context

Looking at `a3p1.c`:
```c
int main() {
    piface_init();
    piface_clear();

    piface_puts("DT8025 - A3P1");
    RPI_WaitMicroSeconds(2000000);
    piface_clear();

    spawn(computePower, 0);     // ← Line 96
    computePrimes(1);           // ← Line 97
}
```

## Answer

After finishing execution of line 96 `spawn(computePower, 0)`, the `freeQ` contains **four threads**:

```
freeQ → [Thread 1] → [Thread 2] → [Thread 3] → [Thread 4] → NULL
```

## Detailed Explanation

### Initial State (Before Line 96)

When `spawn` is called for the **first time**, the system initializes:

```c
static void initializeThreads(void) {
    // ... initialize initp ...

    for (int i=0; i < NTHREADS; i++)  // NTHREADS = 5
    {
        initializeThread(&threads[i], i);
    }
    threads[NTHREADS - 1].next = NULL;
    initialized = 1;
}
```

**After initialization (before spawn executes):**
```
freeQ: [T0] → [T1] → [T2] → [T3] → [T4] → NULL
        ↑
     Points to threads[0]

All 5 thread blocks are available (free)
```

### During spawn(computePower, 0) Execution

**Step 1: Dequeue one thread from freeQ**
```c
newp = dequeue(&freeQ);
```

The `dequeue` operation:
1. Takes the **head** of freeQ (Thread 0)
2. Updates freeQ to point to the **next** element (Thread 1)
3. Returns Thread 0 to be configured

**After dequeue:**
```
freeQ: [T1] → [T2] → [T3] → [T4] → NULL
        ↑
     Points to threads[1]

newp: T0 (removed from freeQ)
```

**Step 2: Configure and enqueue to readyQ**
```c
newp->function = computePower;
newp->arg = 0;
// ... context setup ...
enqueue(newp, &readyQ);  // T0 moves to readyQ
```

Thread 0 is now in readyQ, not in freeQ.

### Final State (After Line 96 Completes)

```
┌─────────────────────────────────────────┐
│ freeQ                                   │
├─────────────────────────────────────────┤
│                                         │
│ [Thread 1] → [Thread 2] → [Thread 3] → [Thread 4] → NULL
│                                         │
│ 4 available thread blocks              │
└─────────────────────────────────────────┘
```

## Important Points

### 1. Resource Pool Management
The freeQ acts as a **pool of available resources**:
- Started with 5 thread blocks
- Used 1 (Thread 0)
- 4 remain available
- Can spawn up to 4 more threads

### 2. Fixed Memory Allocation
```c
#define NTHREADS 5
struct thread_block threads[NTHREADS];
```
- No dynamic memory allocation
- Fixed pool of 5 threads total
- Common pattern in embedded systems
- Prevents memory fragmentation

### 3. Thread Lifecycle in Queues
```
Creation:   freeQ → (spawn) → readyQ
Execution:  readyQ → (dispatch) → RUNNING
Completion: RUNNING → (finish) → freeQ
```

Thread 0: freeQ → readyQ (after line 96)
Threads 1-4: Still in freeQ (available)

### 4. Maximum Concurrent Threads
With 4 threads in freeQ:
- Can create 4 more threads maximum
- After that, `dequeue(&freeQ)` would return NULL
- Would cause system failure (no error handling)

### 5. Thread Recycling
When threads complete execution:
```c
// Inside spawn, after thread finishes
enqueue(current, &freeQ);  // Return to free pool
```
Threads are **recycled**, not destroyed.

## What If We Spawn More Threads?

### After 1 spawn (current state):
```
freeQ: [T1] → [T2] → [T3] → [T4] → NULL  (4 free)
readyQ: [T0] → NULL
```

### After 2 spawns:
```
freeQ: [T2] → [T3] → [T4] → NULL          (3 free)
readyQ: [T0] → [T1] → NULL
```

### After 5 spawns:
```
freeQ: NULL                                (0 free) ⚠️
readyQ: [T0] → [T1] → [T2] → [T3] → [T4] → NULL
```

### Attempt 6th spawn:
```c
newp = dequeue(&freeQ);  // Returns NULL!
newp->function = ...     // CRASH! (null pointer dereference)
```

## Key Takeaway

After line 96, `freeQ` contains **4 available thread blocks** (Threads 1, 2, 3, and 4):

- ✅ 4 threads remain available for future spawn calls
- ✅ Thread 0 was removed (now in readyQ)
- ✅ Threads are linked: T1 → T2 → T3 → T4 → NULL
- ✅ All threads in freeQ are uninitialized (function = NULL, arg = -1)
- ⚠️ System can handle at most 4 more concurrent threads

The freeQ maintains the **pool of unused thread resources** for the system.
