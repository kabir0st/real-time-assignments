3. What is the purpose of the `yield` function? How does it work?

## Purpose of `yield` Function

The `yield` function allows a thread to **voluntarily give up** the CPU to another thread. It implements **cooperative multitasking** where threads explicitly yield control rather than being forcefully preempted. This enables fair sharing of CPU time among multiple threads.

## How `yield` Works - Detailed Explanation

### Function Signature
```c
void yield(void)
```
- Takes no parameters
- Called by the currently running thread to give up the CPU

### Function Code
```c
void yield(void) {
    DISABLE();
    if (readyQ != NULL) {
        thread p = dequeue(&readyQ);
        enqueue(current, &readyQ);
        dispatch(p);
    }
    ENABLE();
}
```

## Step-by-Step Execution Flow

**Step 1: Disable Interrupts (Line 188)**
```c
DISABLE();
```
- Prevents interrupts during the context switch
- Ensures atomic operations on the ready queue
- Critical section begins

**Step 2: Check if Other Threads are Ready (Line 189)**
```c
if (readyQ != NULL) {
```
- Checks if there are any threads waiting to run
- If readyQ is empty, current thread continues running (no yield occurs)

**Step 3: Get Next Thread (Line 190)**
```c
thread p = dequeue(&readyQ);
```
- Remove the first thread from the ready queue
- This thread will run next
- Implements FIFO (First-In-First-Out) scheduling

**Step 4: Move Current Thread to End of Ready Queue (Line 191)**
```c
enqueue(current, &readyQ);
```
- Add the currently running thread to the **back** of the ready queue
- Current thread will run again later (round-robin behavior)
- Ensures fairness - all threads get equal CPU time

**Step 5: Context Switch to Next Thread (Line 192)**
```c
dispatch(p);
```
- Performs the actual context switch
- Saves current thread's CPU state
- Restores next thread's CPU state
- **Execution continues in thread `p`**

**Step 6: Re-enable Interrupts (Line 194)**
```c
ENABLE();
```
- **This line executes when the thread resumes later**
- Re-enables interrupts after the critical section
- When some other thread yields back to this one

## Visual Example: Round-Robin Scheduling

### Initial State
```
readyQ: [Thread B] → [Thread C] → NULL
current: Thread A (running)
```

### Thread A calls yield()

**After dequeue(&readyQ):**
```
readyQ: [Thread C] → NULL
current: Thread A (still, for now)
p: Thread B
```

**After enqueue(current, &readyQ):**
```
readyQ: [Thread C] → [Thread A] → NULL
current: Thread A (still, for now)
p: Thread B
```

**After dispatch(p):**
```
readyQ: [Thread C] → [Thread A] → NULL
current: Thread B (NOW RUNNING)
Thread A: suspended, waiting in readyQ
```

### Thread B calls yield()

**After dequeue(&readyQ):**
```
readyQ: [Thread A] → NULL
current: Thread B
p: Thread C
```

**After enqueue(current, &readyQ):**
```
readyQ: [Thread A] → [Thread B] → NULL
current: Thread B
p: Thread C
```

**After dispatch(p):**
```
readyQ: [Thread A] → [Thread B] → NULL
current: Thread C (NOW RUNNING)
```

### Thread C calls yield()

**After dequeue(&readyQ):**
```
readyQ: [Thread B] → NULL
current: Thread C
p: Thread A
```

**After enqueue(current, &readyQ):**
```
readyQ: [Thread B] → [Thread C] → NULL
current: Thread C
p: Thread A
```

**After dispatch(p):**
```
readyQ: [Thread B] → [Thread C] → NULL
current: Thread A (BACK TO RUNNING)
Thread A resumes from where it yielded!
```

## Key Concepts

### 1. **Cooperative Multitasking**
- Threads must **explicitly call yield()** to give up CPU
- No forced preemption (unless interrupts/timers are added)
- If a thread never yields, other threads never run (starvation)

### 2. **Round-Robin Scheduling**
```
Thread A yields → Thread B runs
Thread B yields → Thread C runs
Thread C yields → Thread A runs
Thread A yields → Thread B runs
... (cycle repeats)
```

### 3. **Fairness Through FIFO Queue**
- dequeue from front: oldest waiting thread runs next
- enqueue to back: yielding thread waits its turn
- All threads get equal opportunities

### 4. **yield() Can Be a No-Op**
If readyQ is empty:
```c
if (readyQ != NULL) {  // FALSE if no other threads
    // Skip the context switch
}
ENABLE();  // Just re-enable interrupts and return
```

### 5. **Where yield() Returns**
Important: `yield()` returns in **two different contexts**:
1. **Immediately**: When readyQ is empty (no context switch)
2. **Much later**: After other threads have run and yielded back

## Example Usage in a3p1.c

```c
void computePower(int seg) {
    for(int n = 0; ; n++) {
        PUTTOLDC("T%d: %d^2=%d\n", seg, n, n*n);
        RPI_WaitMicroSeconds(500000);
        yield();  // Give other threads a chance to run
    }
}

void computePrimes(int seg) {
    for(int n = 0; ; n++) {
        if (is_prime(n)) {
            PUTTOLDC("T%d: Prime %d\n", seg, n);
            RPI_WaitMicroSeconds(500000);
            yield();  // Give other threads a chance to run
        }
    }
}
```

**Execution pattern:**
```
1. computePower: prints "0^2=0", yields
2. computePrimes: prints "Prime 2", yields
3. computePower: prints "1^2=1", yields
4. computePrimes: prints "Prime 3", yields
5. computePower: prints "2^2=4", yields
...
```

## Comparison: With and Without yield()

### Without yield():
```c
void thread1() {
    while(1) {
        // Work forever
        // Other threads NEVER run!
    }
}
```

### With yield():
```c
void thread1() {
    while(1) {
        // Do some work
        yield();  // Give others a turn
    }
}
```

## When yield() is Typically Called

1. **After completing a unit of work**
   ```c
   process_one_item();
   yield();
   ```

2. **In long-running loops**
   ```c
   while(condition) {
       // Work
       yield();  // Share CPU
   }
   ```

3. **When waiting for resources**
   ```c
   while(!resource_available) {
       yield();  // Let others run while waiting
   }
   ```

4. **At regular intervals**
   ```c
   do_work();
   delay(100ms);
   yield();
   ```

## Critical Section Protection

Notice the DISABLE/ENABLE pattern:
```c
DISABLE();              // ← No interrupts
// ... queue operations ...
dispatch(p);            // ← Context switch
ENABLE();               // ← Re-enable interrupts (when resumed)
```

This prevents:
- Race conditions on readyQ
- Interrupts during context switch
- Queue corruption

## Summary

The `yield` function:
1. **Voluntarily gives up** the CPU to another thread
2. **Moves current thread** to the back of the ready queue
3. **Switches to next thread** in the ready queue
4. **Implements round-robin** scheduling (FIFO order)
5. **Enables cooperative multitasking** - threads share CPU fairly
6. **Protects critical sections** with interrupt disabling

`yield()` is the mechanism that makes **concurrent execution** possible in TinyThreads!
