9. In a hypothetical scenario where `computePower` and `computePrimes` do return, which implies that the threads assigned to execute the tasks will terminate, you may need to track which threads terminated. One approach is to keep information about the terminated threads in a list called `doneQ`. Where in `lib/tinythreads.c` would you add a thread that terminated into `doneQ`?

## Answer

A thread that terminated should be added to `doneQ` **inside the `spawn` function, at line 175**, replacing or in addition to the line that currently returns the thread to the free queue.

## Current Implementation (Line 175)

```c
void spawn(void (* function)(int), int arg) {
    thread newp;
    DISABLE();
    if (!initialized)
        initializeThreads();
    newp = dequeue(&freeQ);
    newp->function = function;
    newp->arg = arg;
    newp->next = NULL;
    if (setjmp(newp->context) == 1) {
        ENABLE();
        current->function(current->arg);    // Line 173 - Thread executes
        DISABLE();
        enqueue(current, &freeQ);           // ← Line 175 - CHANGE HERE
        current = NULL;
        dispatch(dequeue(&readyQ));
    }
    SETSTACK(&newp->context, &newp->stack);
    enqueue(newp, &readyQ);
    ENABLE();
}
```

## Where to Add to doneQ

### Location: Line 175

**Current code:**
```c
enqueue(current, &freeQ);  // Returns thread to free pool
```

**Modified code (Option 1 - Track completed threads):**
```c
enqueue(current, &doneQ);  // Add to done queue for tracking
```

**Modified code (Option 2 - Track AND recycle):**
```c
enqueue(current, &doneQ);   // Track in done queue
// Note: Don't return to freeQ immediately
// Could be moved to freeQ later after inspection
```

**Modified code (Option 3 - Both queues):**
```c
// Add to doneQ for tracking
enqueue(current, &doneQ);
// Also return to freeQ for reuse (if doneQ is just for logging)
// But typically you'd choose one or the other
```

## Why This Location?

### Execution Flow When Thread Completes

```
Thread starts (setjmp returns 1)
        ↓
    ENABLE()
        ↓
current->function(current->arg)  ← Thread executes here
        ↓
        ... thread does work ...
        ↓
    return;  ← Function returns (thread completes!)
        ↓
    DISABLE()
        ↓
enqueue(current, &freeQ)  ← Line 175: Thread has terminated!
        ↓                    This is where we should track it
current = NULL
        ↓
dispatch(dequeue(&readyQ))  ← Switch to next thread
```

**Key insight:** Line 175 is executed **immediately after the thread's function returns**, making it the perfect place to record thread termination.

## Complete Modified Implementation

```c
void spawn(void (* function)(int), int arg) {
    thread newp;
    DISABLE();
    if (!initialized)
        initializeThreads();
    newp = dequeue(&freeQ);
    newp->function = function;
    newp->arg = arg;
    newp->next = NULL;
    if (setjmp(newp->context) == 1) {
        ENABLE();
        current->function(current->arg);    // Thread executes
        DISABLE();

        // ========== MODIFICATION HERE ==========
        enqueue(current, &doneQ);           // Track terminated thread
        // Optionally, could still return to freeQ later
        // Or keep in doneQ for inspection
        // =======================================

        current = NULL;
        dispatch(dequeue(&readyQ));
    }
    SETSTACK(&newp->context, &newp->stack);
    enqueue(newp, &readyQ);
    ENABLE();
}
```

## Example with Terminating Functions

### Modified Functions (that return)

```c
void computePower(int seg) {
    for(int n = 0; n < 10; n++) {  // Now has exit condition
        PUTTOLDC("T%d: %d^2=%d\n", seg, n, n*n);
        RPI_WaitMicroSeconds(500000);
        yield();
    }
    // Function returns after 10 iterations
}

void computePrimes(int seg) {
    for(int n = 0; n < 20; n++) {  // Now has exit condition
        if (is_prime(n)) {
            PUTTOLDC("T%d: Prime %d\n", seg, n);
            RPI_WaitMicroSeconds(500000);
            yield();
        }
    }
    // Function returns after checking 20 numbers
}
```

### Execution Timeline

```
Time 1: Both threads spawned
├─ readyQ: [computePower] → NULL
└─ freeQ: [T1] → [T2] → [T3] → [T4] → NULL

Time 2: Threads run, yielding back and forth
├─ computePower: n=0, 1, 2, ..., 9
└─ computePrimes: n=0, 1, 2, ..., 19

Time 3: computePower finishes (n reaches 10)
├─ Function returns
├─ Line 175 executes
├─ enqueue(current, &doneQ)  ← Added to doneQ
└─ doneQ: [computePower thread] → NULL

Time 4: computePrimes continues alone
└─ No other threads in readyQ

Time 5: computePrimes finishes (n reaches 20)
├─ Function returns
├─ Line 175 executes
├─ enqueue(current, &doneQ)  ← Added to doneQ
└─ doneQ: [computePower thread] → [computePrimes thread] → NULL

Time 6: All threads terminated
├─ readyQ: NULL (empty)
├─ doneQ: [T0] → [T1] → NULL (both terminated threads)
└─ Can inspect doneQ to see which threads completed
```

## Alternative Approaches

### Approach 1: Only doneQ (No recycling)
```c
// Line 175
enqueue(current, &doneQ);  // Track completed
// Don't return to freeQ - threads not reused
```
**Use case:** When you want to inspect completed threads later

### Approach 2: doneQ then freeQ (Track and recycle)
```c
// Line 175
enqueue(current, &doneQ);  // First, track it
// Later, periodically move from doneQ to freeQ
// Requires additional cleanup function
```
**Use case:** Want history but also need to recycle threads

### Approach 3: doneQ with metadata
```c
// Line 175
// Could store completion timestamp, exit status, etc.
current->completion_time = get_current_time();
current->exit_status = EXIT_SUCCESS;
enqueue(current, &doneQ);
```
**Use case:** Need detailed termination information

## Why Not Other Locations?

### ❌ Inside yield():
```c
void yield(void) {
    // Wrong location - yield doesn't know if thread is done
    // Threads call yield but continue running
}
```
**Problem:** yield() is for context switching, not termination

### ❌ After dispatch():
```c
dispatch(dequeue(&readyQ));
// Thread has already switched - too late!
enqueue(current, &doneQ);  // current is now NULL anyway
```
**Problem:** After dispatch, we're in a different thread

### ❌ In thread function itself:
```c
void computePower(int seg) {
    for(int n = 0; n < 10; n++) {
        // work...
    }
    enqueue(current, &doneQ);  // Won't work - returns to spawn
}
```
**Problem:** Thread can't clean up itself, returns to spawn's context

## Additional Considerations

### Need to Check for Empty readyQ
```c
if (setjmp(newp->context) == 1) {
    ENABLE();
    current->function(current->arg);
    DISABLE();
    enqueue(current, &doneQ);
    current = NULL;

    // Check if there are more threads to run
    if (readyQ != NULL) {
        dispatch(dequeue(&readyQ));
    } else {
        // All threads completed - system idle
        // Could return to main, enter low-power mode, etc.
    }
}
```

### Utility Function to Inspect doneQ
```c
void printCompletedThreads(void) {
    thread t = doneQ;
    print2uart("Completed threads:\n");
    while(t) {
        print2uart("Thread %d completed\n", t->idx);
        t = t->next;
    }
}
```

## Summary

**Answer:** Add terminated threads to `doneQ` at **line 175** in the `spawn` function.

**Specifically:**
```c
// Line 173: Thread finishes execution (function returns)
current->function(current->arg);

// Line 174: Disable interrupts
DISABLE();

// Line 175: Add to doneQ (MODIFICATION HERE)
enqueue(current, &doneQ);  // Instead of or in addition to freeQ

// Line 176: Clear current pointer
current = NULL;

// Line 177: Switch to next thread
dispatch(dequeue(&readyQ));
```

**Why:** This is the point immediately after a thread's function returns, making it the ideal location to track thread termination before switching to the next thread.
