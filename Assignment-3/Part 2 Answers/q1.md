1. What is the purpose of the `spawn` function? How does it work?

## Purpose of `spawn` Function

The `spawn` function creates a new thread in the TinyThreads system. It allocates a thread control block from the free pool, initializes it with the provided function and argument, sets up its execution context (including stack), and adds it to the ready queue so it can be scheduled for execution.

## How `spawn` Works - Detailed Explanation

### Function Signature
```c
void spawn(void (* function)(int), int arg)
```
- `function`: Pointer to the function that the new thread will execute
- `arg`: Integer argument to pass to that function

### Step-by-Step Execution Flow

#### **Phase 1: Thread Creation (Lines 163-181)**

**Step 1: Disable Interrupts (Line 164)**
```c
DISABLE();
```
- Sets PRIMASK register to disable interrupts
- Prevents race conditions during thread creation
- Ensures atomic operations on shared data structures (queues)

**Step 2: Initialize Thread System (Lines 165-166)**
```c
if (!initialized)
    initializeThreads();
```
- First-time initialization of the thread system
- Sets up the free queue with all available thread blocks
- Only happens once when the first thread is spawned

**Step 3: Allocate Thread Block (Line 167)**
```c
newp = dequeue(&freeQ);
```
- Removes a thread_block from the free queue
- This gives us a pre-allocated memory structure to store thread information
- `newp` now points to an available thread control block

**Step 4: Configure Thread (Lines 168-170)**
```c
newp->function = function;
newp->arg = arg;
newp->next = NULL;
```
- Store the function pointer the thread will execute
- Store the argument to pass to that function
- Clear the next pointer (will be used for queue linking)

**Step 5: Create Execution Context (Line 171)**
```c
if (setjmp(newp->context) == 1) {
    // This code runs LATER when thread actually executes
}
```
- **First call to setjmp returns 0** - continues to line 179
- **Saves the CPU state (registers, program counter) in newp->context**
- When longjmp is later called with this context, setjmp returns 1

**Step 6: Setup Stack (Line 179)**
```c
SETSTACK(&newp->context, &newp->stack);
```
- Modifies the saved context to use the thread's own stack
- Sets the stack pointer in the context to point to the thread's 1KB stack space
- Essential for thread isolation - each thread needs its own stack

**Step 7: Add to Ready Queue (Line 180)**
```c
enqueue(newp, &readyQ);
```
- Places the new thread in the ready queue
- Thread is now ready to be scheduled
- Waits for dispatcher to select it

**Step 8: Re-enable Interrupts (Line 181)**
```c
ENABLE();
```
- Clears PRIMASK register
- Allows interrupts again
- Critical section complete

#### **Phase 2: Thread Execution (Lines 171-177)**

This code runs **later** when the scheduler dispatches this thread:

**Step 1: Thread Starts (Line 171-172)**
```c
if (setjmp(newp->context) == 1) {
    ENABLE();
```
- When dispatch() calls longjmp(newp->context, 1), execution jumps here
- setjmp now returns 1 (not 0)
- Re-enable interrupts (they were disabled during context switch)

**Step 2: Execute Thread Function (Line 173)**
```c
current->function(current->arg);
```
- **This is where the actual thread work happens**
- Calls the user-provided function with the argument
- Thread runs until function completes

**Step 3: Thread Cleanup (Lines 174-177)**
```c
DISABLE();
enqueue(current, &freeQ);
current = NULL;
dispatch(dequeue(&readyQ));
```
- Disable interrupts for cleanup
- Return thread block to free queue (recycling)
- Clear current thread pointer
- Dispatch next thread from ready queue

### Key Concepts

#### **1. setjmp/longjmp Mechanism**
- `setjmp`: Saves the current execution context (registers, PC, stack pointer)
- `longjmp`: Restores a previously saved context and jumps to it
- **First call**: setjmp returns 0 (saves context)
- **After longjmp**: setjmp returns non-zero value (restores context)

#### **2. Context Switching**
The spawn function creates the initial context for a thread. When the scheduler later calls:
```c
dispatch(newp);  // which does longjmp(newp->context, 1)
```
The CPU state is restored to the saved context, and execution continues from where setjmp was called, but this time it returns 1.

#### **3. Stack Management**
Each thread gets its own 1KB stack space:
```c
char stack[STACKSIZE];  // 1024 bytes per thread
```
The SETSTACK macro modifies the saved context to use this stack, ensuring thread isolation.

#### **4. Thread Lifecycle**
```
freeQ → (spawn) → readyQ → (dispatch) → RUNNING → (finish) → freeQ
```

#### **5. Critical Sections**
DISABLE/ENABLE pairs protect critical sections:
- Queue manipulation (enqueue/dequeue)
- Thread state changes
- Context switching

### Example Usage

```c
void my_thread(int arg) {
    print2uart("Thread %d running\n", arg);
    // Do work...
}

int main() {
    spawn(my_thread, 1);  // Creates thread that will print "Thread 1 running"
    spawn(my_thread, 2);  // Creates another thread with arg=2
    // Threads are now in readyQ, waiting to be scheduled
}
```

### Summary

The `spawn` function:
1. **Allocates** a thread control block from the free pool
2. **Configures** it with the function and argument
3. **Creates** an execution context using setjmp
4. **Sets up** an isolated stack for the thread
5. **Queues** the thread for execution in the ready queue
6. **Protects** all operations with interrupt disabling

The actual thread execution happens **later** when the dispatcher selects it from the ready queue and performs a context switch using longjmp.
