5. After finishing the execution of line 96 (spawn(computePower, 0)), describe the content of `readyQ`.

## Context

Looking at `a3p1.c`:
```c
int main() {
    piface_init();
    piface_clear();

    piface_puts("DT8025 - A3P1");
    RPI_WaitMicroSeconds(2000000);
    piface_clear();

    spawn(computePower, 0);     // ← Line 96
    computePrimes(1);           // ← Line 97
}
```

## Answer

After finishing execution of line 96 `spawn(computePower, 0)`, the `readyQ` contains **one thread**:

```
readyQ → [Thread 0: computePower, arg=0] → NULL
```

## Detailed Explanation

### Initial State (Before Line 96)

**Before any threads are created:**
```
freeQ: [T0] → [T1] → [T2] → [T3] → [T4] → NULL
readyQ: NULL (empty)
current: &initp (initial process)
```

### During spawn(computePower, 0) Execution

**Step 1: Initialize threads (first spawn call)**
```c
if (!initialized)
    initializeThreads();
```
Thread system is initialized.

**Step 2: Allocate thread from freeQ**
```c
newp = dequeue(&freeQ);
```

**After dequeue:**
```
freeQ: [T1] → [T2] → [T3] → [T4] → NULL
readyQ: NULL
newp: T0
```

**Step 3: Configure the thread**
```c
newp->function = computePower;
newp->arg = 0;
newp->next = NULL;
```

**Thread T0 configuration:**
```
T0.function = computePower
T0.arg = 0
T0.next = NULL
```

**Step 4: Create context**
```c
if (setjmp(newp->context) == 1) {
    // Skipped (returns 0 on first call)
}
SETSTACK(&newp->context, &newp->stack);
```
- Context saved (returns 0)
- Stack pointer configured
- Skip the if-block

**Step 5: Add to readyQ**
```c
enqueue(newp, &readyQ);
```

**After enqueue:**
```
freeQ: [T1] → [T2] → [T3] → [T4] → NULL
readyQ: [T0] → NULL                          ← ONE THREAD
current: &initp
```

**Step 6: spawn() returns**
```c
ENABLE();
// spawn returns to main
```

### Final State (After Line 96 Completes)

```
┌─────────────────────────────────────────┐
│ readyQ                                  │
├─────────────────────────────────────────┤
│ [Thread 0]                              │
│   ├─ function: computePower             │
│   ├─ arg: 0                             │
│   ├─ next: NULL                         │
│   ├─ context: saved CPU state           │
│   └─ stack: 1KB allocated               │
└─────────────────────────────────────────┘
```

## Thread Details

### Thread 0 (in readyQ)
```c
threads[0].idx = 0
threads[0].function = computePower  // Function pointer
threads[0].arg = 0                  // Argument to pass
threads[0].next = NULL              // Last (only) in queue
threads[0].context = {...}          // Saved CPU state with setjmp
threads[0].stack[1024] = {...}      // 1KB stack allocated
threads[0].Period_Deadline = INT_MAX
threads[0].Rel_Period_Deadline = INT_MAX
```

## Important Points

### 1. Thread is NOT Running Yet
- Thread is **queued**, not executing
- `computePower(0)` has NOT been called yet
- Thread will run when dispatched by scheduler

### 2. spawn() Returns Immediately
```c
spawn(computePower, 0);  // Creates thread, adds to queue, returns
// Execution continues here immediately
// computePower is not running yet!
```

### 3. Queue Size
- **Exactly 1 thread** in readyQ
- Only one thread has been spawned so far
- Main process is still running

### 4. What Hasn't Happened
- ❌ `computePower()` not called
- ❌ No context switches yet
- ❌ No yield() calls yet
- ❌ Thread T0 is queued but suspended

### 5. What Will Happen Next (Line 97)
```c
computePrimes(1);  // ← Next line
```
- Main calls `computePrimes(1)` directly (not spawned)
- `computePrimes` will call `yield()`
- `yield()` will dispatch Thread T0
- Then `computePower(0)` actually starts running
