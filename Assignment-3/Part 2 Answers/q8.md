8. Although functions `computePower` and `computePrimes` never return, they execute concurrently in the `a3p1.img` kernel. How is this achieved?

## Answer

Concurrent execution of `computePower` and `computePrimes` is achieved through **cooperative multitasking** using the `yield()` function, which performs **context switching** between threads.

## How Concurrency is Achieved

### The Key Mechanism: yield()

Both functions contain `yield()` calls in their infinite loops:

```c
void computePower(int seg) {
    for(int n = 0; ; n++) {                      // Infinite loop
        PUTTOLDC("T%d: %d^2=%d\n", seg, n, n*n);
        RPI_WaitMicroSeconds(500000);
        yield();  // ← Gives up CPU voluntarily
    }
    // Never returns
}

void computePrimes(int seg) {
    for(int n = 0; ; n++) {                      // Infinite loop
        if (is_prime(n)) {
            PUTTOLDC("T%d: Prime %d\n", seg, n);
            RPI_WaitMicroSeconds(500000);
            yield();  // ← Gives up CPU voluntarily
        }
    }
    // Never returns
}
```

### Round-Robin Execution

                       │ Context Switch
                       ▼
Iteration 2:
┌──────────────────────────────────────┐
│ 3. computePrimes runs (resumed)      │

│    - Prints "T0: 1^2=1"              │

                       ▼

## Detailed Execution Flow

### Step-by-Step: How yield() Creates Concurrency

**When computePrimes calls yield():**

```c
void yield(void) {
    DISABLE();                          // Disable interrupts
    if (readyQ != NULL) {
        thread p = dequeue(&readyQ);    // Get next thread (computePower)
        enqueue(current, &readyQ);      // Put computePrimes at back of queue
        dispatch(p);                    // Switch to computePower
    }
    ENABLE();                           // Re-enable interrupts (when resumed)
}
```

**What happens:**
1. **Save computePrimes' state** (where it is in its loop, local variables, etc.)
2. **Remove computePower from ready queue**
3. **Put computePrimes at back of ready queue**
4. **Restore computePower's state**
5. **Continue execution in computePower**

**When computePower calls yield():**
- Same process in reverse
- Switches back to computePrimes
- computePrimes resumes where it left off

## Queue State Changes

### State 1: computePrimes running
```
readyQ: [computePower] → NULL
current: computePrimes (RUNNING)
```

### computePrimes calls yield() → State 2
```
readyQ: [computePrimes] → NULL
current: computePower (RUNNING)
```

### computePower calls yield() → State 3
```
readyQ: [computePower] → NULL
current: computePrimes (RUNNING)
```

**Pattern:** Threads alternate in a round-robin fashion

## Time-Sliced Execution

### Without yield() (Hypothetical):
```c
void computePower(int seg) {
    for(int n = 0; ; n++) {
        PUTTOLDC("T%d: %d^2=%d\n", seg, n, n*n);
        // No yield() - runs forever!
    }
}
```
**Result:**
- First function to run monopolizes CPU
- Other function never executes
- No concurrency

### With yield() (Actual):
```c
void computePower(int seg) {
    for(int n = 0; ; n++) {
        PUTTOLDC("T%d: %d^2=%d\n", seg, n, n*n);
        yield();  // Share CPU
    }
}
```
**Result:**
- Functions alternate execution
- Both make progress
- Appears to run simultaneously (concurrency)

## Key Components Enabling Concurrency

### 1. **Context Saving/Restoration (setjmp/longjmp)**
```c
// Save current thread
setjmp(current->context);

// Restore other thread
longjmp(next->context, 1);
```

### 2. **Separate Stacks**
```c
struct thread_block {
    ...
    char stack[STACKSIZE];  // Each thread has own stack
};
```
- Each thread has isolated 1KB stack
- Prevents interference between threads
- Preserves local variables

### 3. **Ready Queue (readyQ)**
```c
thread readyQ = NULL;
```
- Maintains list of runnable threads
- FIFO order ensures fairness
- Enables round-robin scheduling

### 4. **yield() Function**
```c
void yield(void) {
    // Voluntary context switch
    // Move current thread to back of queue
    // Run next thread from front of queue
}
```

### 5. **dispatch() Function**
```c
static void dispatch(thread next) {
    // Perform actual context switch
    // Save current, restore next
}
```

## Cooperative vs Preemptive Multitasking

### This System: Cooperative
```
✓ Threads voluntarily yield
✓ Thread controls when to give up CPU
✗ Thread can hog CPU if it doesn't yield
✗ No forced preemption
```

### Alternative: Preemptive (Not implemented here)
```
✓ Timer interrupts force context switches
✓ Threads automatically preempted
✓ No starvation risk
✗ More complex implementation
```

## Why Functions Never Return But Still Work

### Traditional (Single-threaded):
```c
void function() {
    for(int n = 0; ; n++) {
        // Work
    }
    // Never returns - blocks forever
}

main() {
    function();  // Program stuck here forever
}
```

### With Threading:
```c
void function() {
    for(int n = 0; ; n++) {
        // Work
        yield();  // Temporarily give up CPU
    }
    // Never returns - but doesn't block!
}

main() {
    spawn(function, 0);  // Creates thread, returns immediately
    other_function();    // Continues executing
}
```

## Summary

Concurrent execution is achieved through:

1. **yield()** - Threads voluntarily give up the CPU
2. **setjmp/longjmp** - Save and restore thread contexts
3. **Separate stacks** - Each thread has isolated execution environment
4. **Ready queue** - Manages which thread runs next
5. **Round-robin scheduling** - Fair CPU time distribution
6. **Context switching** - Rapidly alternates between threads

**Result:** Both infinite loops make progress by taking turns running, creating the illusion that both are executing simultaneously even though only one runs at any given moment on the single CPU.

This is **cooperative multitasking** - the foundation of concurrent programming in TinyThreads.
